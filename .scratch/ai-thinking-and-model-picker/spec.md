# Spec: AI 配置支持思考能力设置 + 获取模型后下拉选择

Labels: ready-for-agent

## Problem Statement

用户在「AI 接入设置」里配置 OpenAI 兼容的模型网关时，有两个痛点：

1. **思考能力不可控**。推理型模型（o 系、DeepSeek-R1、Qwen 思考模式等）有的默认开思考、有的需要显式开启，还有的思考太深导致响应慢、成本高。当前配置表单没有任何思考相关设置，服务端构建的请求体也从不携带思考参数，用户无法控制模型"想不想、想多深"。
2. **选模型只能靠联想**。点击「获取模型列表」后，模型 ID 仍是一个普通输入框，只靠 `<datalist>` 提供输入联想。网关返回几十上百个模型时，datalist 联想在部分浏览器里体验很差，用户希望能真正"点选"一个模型。

## Solution

1. **思考能力设置**：每套 AI 配置新增一个思考档位设置——「关闭 / 低 / 中 / 高」。保存后随每轮对话请求发送给模型服务：
   - 关闭：请求体不携带任何思考字段（与现状完全一致，零回归风险）。
   - 低/中/高：按协议映射为标准思考档位字段（Chat Completions → `reasoning_effort`；Responses → `reasoning.effort`）。
2. **模型下拉选择**：设置页「获取模型列表」成功后，模型 ID 字段升级为可搜索下拉（combobox）——列表项可直接点选、支持按关键字过滤；同时保留手填任意模型 ID 的能力（网关不提供 /models、或需要使用列表之外的网关路由名时不受影响）。

## User Stories

1. As a 用户, I want 为每套 AI 配置设置思考档位（关闭/低/中/高）, so that 我能控制推理型模型是否思考以及思考多深。
2. As a 用户, I want 思考设置随配置一起保存在服务端, so that 切换默认配置后新对话自动使用对应的思考行为，无需每轮手动调整。
3. As a 用户, I want 思考档位设为"关闭"时请求完全不携带思考字段, so that 不支持思考参数的旧网关/模型不受任何影响。
4. As a 用户, I want 思考档位设为低/中/高时请求按协议携带标准档位字段, so that 支持 effort 语义的模型按预期深度思考。
5. As a 用户, I want 在保存配置前就能看到当前思考设置, so that 编辑已有配置时能确认它的思考行为。
6. As a 用户, I want 无效的思考档位被服务端拒绝并得到可读的错误提示, so that 不会把坏配置静默存进数据库。
7. As a 用户, I want 点击「获取模型列表」后能在一个真正的下拉里点选模型, so that 不用在输入框里凭记忆敲模型 ID。
8. As a 用户, I want 下拉支持按关键字过滤, so that 网关返回上百个模型时能快速定位目标。
9. As a 用户, I want 下拉打开时仍能自由输入列表里没有的模型 ID, so that 使用网关自定义路由名或网关不提供 /models 时不受影响。
10. As a 用户, I want 获取模型列表失败时看到明确的错误提示且仍可手填, so that 列表功能故障不阻塞我完成配置。
11. As a 用户, I want 已选中的模型 ID 在下拉关闭后仍显示在输入框中并可继续编辑, so that 选中后还能微调（例如改版本号后缀）。
12. As a 用户, I want 新建配置时思考档位默认为"关闭", so that 升级后所有既有行为和既有配置保持不变。
13. As a 用户, I want 通过环境变量兜底的模型配置默认使用"关闭"档位, so that 未显式配置思考的部署行为与升级前完全一致。
14. As a 用户, I want 思考设置与协议格式（Chat Completions / Responses）独立, so that 切换协议时思考意图仍然保留。
15. As a 运维/部署者, I want 数据库中的旧配置在升级后自动获得"关闭"思考档位, so that 无需手动迁移。

## Implementation Decisions

- **数据模型**：AI 配置（provider）增加单字段思考档位：`off | low | medium | high`，`off` 为默认值。用单字段而非「开关 + 独立档位」两个字段，消除非法组合状态（"开启"但没选档位）。服务端校验为严格枚举；数据库新增列，旧行迁移为 `off`。
- **API 契约**：配置的创建/更新请求体接受可选 `thinking` 字段；公开的 provider payload 返回该字段（非敏感信息，直接透出）。环境变量兜底配置（providerFromEnv）固定为 `off`。
- **请求体映射**：映射集中在模型适配器的请求构建逻辑一处：
  - `off` → 请求体不包含任何思考字段。
  - `low | medium | high` → Chat Completions 协议发送 `reasoning_effort: <档位>`；Responses 协议发送 `reasoning: { effort: <档位> }`。
  - **不**自动发送 `enable_thinking`（Qwen/DashScope 风格）或 `thinking`（GLM 风格）等厂商私有字段：OpenAI 官方接口会对未知参数返回 400，盲目附带会破坏严格校验的网关。私有参数映射留作后续按需扩展（见 Out of Scope / Further Notes）。
- **模型下拉（combobox）**：保留 `<input>` 承接手填与选中值，列表存在时在其下方弹出可过滤的选项浮层（不用原生 `<select>`，因为必须保留自由输入）。过滤为前端本地过滤即可（列表已一次性拉回），不新增后端接口。现 `<datalist>` 移除。
- **接口复用**：获取模型列表继续走现有接口（表单未保存 → POST 探测式获取；已保存 → GET 按已存密钥获取），无后端改动。
- **UI 状态**：思考档位控件放在协议格式字段附近；能力探测结果区不承载思考信息（思考属于配置意图，不是探测结论）。

## Testing Decisions

- **只测外部行为**：不测内部函数拆分或状态细节。断言"给定这套配置，发出的请求体长这样"和"在页面上做这个操作，看到这个结果"。
- **思考参数映射**：在模型适配器的请求构建缝隙上测——现有 server 端 AI 配置 API 测试已有"桩 fetch、断言出站请求体"的先例，直接扩展：分别覆盖 off（断言无思考字段）、三档开启值 × 两种协议（断言对应字段与值）、以及旧数据默认 off 的行为。
- **服务端校验/持久化**：同一 API 测试文件内覆盖非法档位被拒、合法档位存取回读、公开 payload 不泄漏敏感字段的前提下返回 thinking。
- **设置页交互**：浏览器套件新增一个 AI 设置页测试文件，沿用现有浏览器测试模式：驱动「获取模型列表」→ 断言下拉出现、点选后输入框获得该 ID、关键字过滤生效、手填列表外 ID 可保存；驱动思考档位控件 → 保存后重新打开编辑确认回显。
- **前端 domain 归一化**：沿用前端单测既有模式覆盖 thinking 字段与模型列表响应的归一化（含服务端未返回 thinking 时的默认 off）。

## Out of Scope

- 聊天面板内按轮次切换思考档位（本期思考设置只随配置保存）。
- 厂商私有思考参数（`enable_thinking`、`thinking: { type }` 等）的自动映射。
- 「思考完成」折叠摘要的展示逻辑变更（现有行为保持不变）。
- 模型列表的服务端缓存、分页、模糊搜索。
- temperature / top_p / max tokens 等其他采样参数的配置化。
- 模型能力（是否支持思考）的自动探测。

## Further Notes

- 探测式获取模型列表使用的是表单里当前手填的密钥；下拉不影响该流程，只是消费它的结果。
- 映射函数应保持单点集中：后续若要为特定网关追加 `enable_thinking` 等私有字段映射，只改这一处并补对应断言即可。
- datalist → combobox 是同一字段的交互替换，注意浏览器测试里旧的 datalist 选择方式若被引用需同步更新（现有套件未引用该字段，预期无影响）。
