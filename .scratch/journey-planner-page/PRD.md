# PRD：AI 行程规划工作台（Journey Planner）

> 调研对象：[圆周旅迹 · 呼伦贝尔经典环线7日自驾](https://www.pitravel.cn/plan/journey/7684289455784327927?source=home)
> 调研日期：2026-09-12 ｜ 调研方式：真实浏览器实测（截图与交互记录见附录 A）
> 状态：Draft ｜ 作者：Eamon + ZCode

---

## 1. 背景与目标

### 1.1 背景

旅行行程规划目前普遍割裂在多个工具里：攻略在社交平台、记录在文档/表格、地图路线在地图 App、讨论在聊天群。用户在"查攻略 → 排日程 → 定住宿 → 算车程 → 拉群同步"之间反复横跳，且修改一处（如换一晚酒店）需要人工重排整条线路。

调研对象（圆周旅迹 pitravel）将 **AI 对话式规划、可视化行程画布、路线地图** 三者合并到单一工作台页面，AI 的每一次回复都能直接落库为结构化行程，并通过画布/地图实时呈现。本 PRD 基于对该页面的实测，定义同等能力的产品需求，作为本项目（travles）行程规划功能的实现依据。

### 1.2 产品目标

| 目标 | 衡量指标 |
| --- | --- |
| 用对话即可产出"可用、可改、可分享"的结构化行程 | 首次会话结束即形成完整行程（含每日主题、点位、交通段、住宿）的比例 ≥ 70% |
| 修改成本低：改一处约束，AI 自动重排受影响天数 | 单次约束变更后用户手动修补天数 ≤ 1 天 |
| 行程可交付：一键分享给同行人查看 | 分享链接创建成功率 100%，打开即见最新版本 |
| 三视图一致：对话、画布、地图始终展示同一份数据 | 任意视图编辑后，其余视图同步延迟 < 1s |

### 1.3 非目标（本期不做）

- 交易闭环：不在线订酒店/门票/租车（仅展示参考信息与外部链接）。
- 多人实时协同编辑（本期只做"链接可见性"式分享查看）。
- 移动端原生 App（本期为 Web 响应式，桌面优先）。

## 2. 用户与核心场景

### 2.1 目标用户

- **发起人（规划者）**：家庭/朋友出行的组织者，负责定线路、订住宿。
- **同行人（查看者）**：通过分享链接查看行程，本期只读。

### 2.2 核心场景（均来自实测对话）

1. **冷启动规划**："我打算去呼伦贝尔市玩 7 天，走经典路线" → AI 先给环线框架（海拉尔→莫尔格勒河/额尔古纳→恩和/室韦→卡线→黑山头→满洲里→呼伦湖→海拉尔），**先澄清关键变量**（出行方式？自驾/包车/公共交通），用户点选选项 chips 后再细化，最终产出 D1–D7 完整行程 + 关键提醒（预约、边防证、天气、还车时间），并写入行程画布与地图。
2. **硬约束对齐**：用户给出航班时间（"10月2号晚上8点到海拉尔，10月8号下午3点起飞"）→ AI 只重排 D1（晚到版）与 D7（返程版），并说明时间缓冲；同时**主动抛出权衡问题**（保呼伦湖还是保返程余量？D1 深夜到要不要订当晚酒店？）。
3. **住宿约束与冲突消解**：用户说"10/2 和 10/7 都住全季酒店（机场成吉思汗广场店）" → AI 识别出 **10/7 原计划住满洲里，与约束冲突**，明确指出冲突并给出选项（调整整条环线让满洲里提前）；用户点选后 AI 重排全环线（满洲里提前到 D5），逐日回写日期、安排、住宿。
4. **逐项补全**：用户逐晚提供酒店（"10月3号住 Ease 云逸庭苑"）→ AI 更新对应住宿卡，附带 POI 富信息（评分 4.8、木刻楞民宿、含早餐、位置），并**汇报剩余未定项**（"还剩 3 晚没定，需要我帮你看恩和、黑山头、满洲里的酒店参考吗？"），同时给出快捷追问 chips。
5. **手动微调**：用户在画布上直接拖拽卡片排序、增删点位、跨天移动/复制；或切换到列表视图按天核对。

## 3. 信息架构与页面布局

### 3.1 页面结构（桌面端）

```
┌──────────────────────────────────────────────────────────────────────────┐
│ 顶栏: [← 返回] [行程标题] [📅 10.02至10.08 7天6晚]   [可见性▾] [📖] [分享] [⋯] │
├──────────────┬──────────────────────────────────────┬────────────────────┤
│ 左栏 AI 助手  │        中栏 行程画布 / 列表            │   右栏 路线地图      │
│ (圆周AI)      │  按天分栏卡片，横向滚动                │   多日彩色路线+POI  │
│ ~25% 宽      │              ~50% 宽                  │      ~25% 宽       │
│ 可收起        │  可收起                               │   可收起            │
└──────────────┴──────────────────────────────────────┴────────────────────┘
```

- 三栏均可独立收起（"收起"按钮），收起后其余栏自动扩展；左栏右缘有**拖拽调宽**手柄。
- 中栏提供两种视图：**画布（canvas）**——按天纵向排列卡片、天与天横向排布、整体横向滚动；**列表（list）**——单日逐项纵向时间线，顶部有天签 tab 可切换日期。
- 右栏地图基于高德（页面依赖 `amap`），可独立缩放/定位。

### 3.2 顶栏

| 元素 | 说明 |
| --- | --- |
| 返回 | 返回行程列表/首页（首页有"开始计划下一段旅程"入口） |
| 行程标题 | 如"呼伦贝尔经典环线7日自驾"，可由 AI 首轮生成、可编辑 |
| 日期区间徽章 | "10.02至10.08 7天6晚"，随起止日期自动计算天数/晚数 |
| 可见性下拉 | 当前值"获得链接者可见"——拥有链接即可查看；可选更严格（仅邀请/仅自己，具体档位见 §7.4） |
| 图册图标 | 行程图库入口 |
| 分享 | 生成/复制分享链接 |
| 更多操作 ⋯ | 行程级操作（重命名、删除、导出等） |

## 4. 功能需求

### 4.1 左栏：AI 助手（对话式规划）

**F1 会话流**
- 消息分用户/AI 两侧；AI 消息支持 Markdown（标题、加粗、列表、行内 **POI 链接**——点击地点名联动地图定位）。
- AI 消息首部有"**思考完成**"可折叠推理段；尾部有"**复制**"与"**来源**"（来源可展开查看引用）。
- 输入框：占位文案"旅行大小事，都能问圆周"，支持多行，发送按钮；另有"**智能解析**"（把粘贴的长文本攻略解析为结构化行程项）与"**路线优化**"（对现有行程做全局优化建议）两个快捷能力按钮。

**F2 澄清式规划（关键行为）**
- AI 不直接输出完整计划：先给框架，识别"直接影响整体安排"的关键变量并**一次只问一个**，同时给出**可点选的选项 chips**（如出行方式：🚗 自驾/租车自驾；✈️ 飞到当地后租车；……）。点击 chip 即作为用户回复发送。
- 澄清维度至少覆盖：出行方式与车辆安排、起止日期与航班车次硬约束、住宿约束（指定酒店/每晚落脚城市）、预算与节奏偏好。
- AI 产出的正式计划必须包含：**行程概览**（逐日主题 + 主要安排 + 住宿）与**关键提醒**（预约限制、证件、天气穿衣、还车/返程缓冲、沿途补给等）。

**F3 行程回写（AI → 结构化数据）**
- AI 确认约束后，把计划**直接写入**行程模型（天数、每日主题、点位卡、交通段、住宿卡），画布与地图即时同步。
- 回写时对未确认的槽位采用"**默认填充 + 显式声明**"策略："恩和、室韦的民宿和几段车程我按常规情况填了"——占位项在画布上标记为待定。

**F4 农夫式确认与权衡（修改类指令）**
- 涉及既有计划的修改时，AI 先**复述识别到的变更与其影响**（例如指出 10/7 住宿与原计划冲突），给出处理选项 chips，用户选择后再执行。
- 执行后**汇报结果**：逐日列出新的日期/安排/住宿；对为满足约束而做的妥协（如国门游览压缩）主动说明。
- 每轮结尾给出**下一步建议问题**，并渲染为可点击 chips（"帮我看恩和、黑山头、满洲里三晚的酒店参考" / "这家民宿离景区多远" / "10/4 午餐晚餐有什么推荐"）。

**F5 会话持久化**：对话与行程同属一个 trip，刷新/再次进入可回看全部历史。

### 4.2 中栏：行程画布（Canvas）与列表（List）

**F6 天分组（Day Column）**
- 每天一列：天签（"10.02 周五"，按日着色）+ **当日主题**（"海拉尔集结"）+ 卡片纵向排列 + 列尾"+"添加卡。
- 画布横向滚动，天与天之间无强分隔线，用点状画布底纹区分；支持整体缩放（左下 +/−）。

**F7 卡片（Event Card）**
- 类型及视觉：**交通**（灰紫签）/ **住宿**（蓝签）/ **游玩**（绿签）/ **其他**（灰签）；美食类预期同样支持。
- 卡片构成：封面图（可"添加图片"）、类型签、序号（当日顺序号）、POI 名称、一句话备注（如"20:00抵达，机场办理租车提车，备好身份证"）、右上"⋯"菜单。
- **纯文本卡**：无 POI 的活动项（如"自驾前往满洲里""入住满洲里酒店，逛中苏金街"）渲染为无图文本条。
- 选中态：卡片出现左侧悬浮工具条——**拖拽手柄**、AI 按钮（针对该卡片提问/优化）、**路线同步**按钮、"添加"按钮；卡片本体高亮描边，地图同步高亮对应 POI。

**F8 交通段（Leg）**
- 相邻两卡之间显示驾车距离与时长（"30.3千米 31分钟 >"），点击可展开/重新规划路线。
- 跨天首卡与前一日末卡之间同样显示（画布上表现为新列顶部一条接续段）。

**F9 卡片操作菜单（⋯）**：上移一位 / 下移一位 / **移动到（跨天）** / **复制到（跨天）** / 删除。

**F10 天级操作**：列表视图中天签行提供"魔法棒"（AI 优化这一天）与"⋯"（编辑主题、增删天等）。

**F11 侧边工具（Tools）**
- 画布左侧竖排："工具"入口 + 三个停靠面板：**便签**（自由文本）、**清单**（待办/checklist，如"带身份证""提前2天预约莫尔格勒河"）、**图库**（行程相册）。
- 视图切换器：**画布 / 列表** 二态切换。

**F12 添加点位**：每列"+"与选中卡工具条"+"均新增卡片；支持搜索 POI 或自由文本。

### 4.3 右栏：路线地图

**F13 多日路线渲染**
- 高德地图上按日绘制驾车路线 polyline，**每日一色**，路线带行车方向刻度。
- 每日路线中点悬浮**日程标签**："10.05 周一 185km"（日签颜色与画布一致）；点击天签联动画布滚到对应列。
- POI 序号标记（当日顺序），有碰撞隐藏策略（`poi-marker-name--hidden-by-collision`）。

**F14 POI 详情卡**（点击标记或画布卡片触发）
- 顶部：地图视野自动聚焦该 POI，右上显示**当前日下拉**（"10.03 周六 ▾"）可切日。
- 详情卡：POI 名称、⭐评分、类型签（景点/酒店/餐饮…）、图片轮播（左右翻页 + 页码"1/⋯"）、"**为你介绍此地**"摘要、"了解更多 ↗"外链、"⭐ 收藏"按钮。
- 关闭后回到全览。

**F15 地图底部工具条**
- **推荐** toggle（开）：在地图上叠加推荐 POI 呼啦圈/气泡（如沿途观景营地），可点击加入行程或收藏。
- **待计划**：收纳"收藏/推荐但未安排进日程"的点位，可拖入画布某天。
- **收藏**：收藏夹列表。
- **展开**：展开完整侧栏。
- 筛选行：**全部地区**（地域下拉）、类型 chips 带计数（"游玩·15""其他·10"）。

**F16 地图控件**：全图（fit 总览）、我的位置、缩放 +/−；右上"总览 ▾"切换视野模式（总览/按日）。

### 4.4 AI 接入：用户自定义（BYO Model）

AI 能力不绑定平台方自带的模型服务，由用户在设置中**自行接入**兼容 OpenAI 协议的服务商（官方 OpenAI、各类中转/代理、自建 vLLM 等）。本产品侧不代理、不托管密钥以外的模型凭据。

**F-AI1 接入配置**
- 设置项：`名称`（多配置可命名，如"公司中转"）、`协议格式`（二选一，见 F-AI2）、`Base URL`（如 `https://api.openai.com/v1`）、`API Key`、`模型 ID`（如 `gpt-4o`，自由填写，不内置模型列表；可选"获取模型列表"按钮调 `GET /models` 校验）、可选 `自定义请求头`（JSON，用于中转网关鉴权）。
- 支持保存**多套配置**并可切换/设为默认；每套配置提供"连通性测试"（发一条最小请求验证 Key/模型可用）。
- API Key 仅存本地（浏览器存储或用户自托管后端），永不随 trip 分享数据导出。

**F-AI2 支持两种 OpenAI 协议格式（可切换）**
1. **Chat Completions**（`POST {base}/chat/completions`）——经典格式：
   - `messages` 数组承载系统/用户/助手消息；`tools` + `tool_calls` 承载 `TripPatch` 结构化回写（function calling）。
   - 流式用 `stream: true`（SSE，`chat.completion.chunk`）。
   - 兼容不支持原生 function calling 的服务：降级为"在系统提示中约定 JSON schema，从 `content` 中解析 JSON"。
2. **Responses**（`POST {base}/responses`）——新格式：
   - `input`（含 `instructions`/消息项）、`tools`（function 工具定义）、`previous_response_id` 做多轮上下文衔接。
   - 事件流（`response.output_text.delta` 等）做流式渲染。
   - 模型的结构化回写通过 function tool 调用参数返回。

**F-AI3 适配层要求**
- 前端/后端只面向内部统一会话接口（见附录 B），由 **Provider 适配层**把统一协议翻译为上述任一格式；新增格式只改适配层。
- 能力探测：部分自建服务不支持流式或 function calling——保存配置时探测并降级（非流式轮询/JSON-in-content 解析），降级后在设置中明示。
- 失败处理：401/429/超时给出明确错误与"去设置检查配置"入口；单次会话中切换配置后，上下文（消息历史）保持不变，仅换推理后端。
- 兼容性说明写进设置页：推荐支持 function calling 的模型（结构化回写体验最佳），纯文本模型可用但行程回写准确率下降。

### 4.5 三栏联动（核心机制）

| 触发 | 联动表现 |
| --- | --- |
| AI 回写行程 | 画布新增/重排天与卡；地图重绘路线与新 POI |
| 点击画布卡片 | 卡片选中态；地图飞到对应 POI 并弹详情卡 |
| 点击 AI 消息中的 POI 链接 | 地图定位该 POI |
| 地图点击标记 | 画布滚动至对应日并高亮卡片 |
| 画布拖拽排序 | 交通段重算（距离/时长刷新）；地图序号与路线更新 |
| 可见性/分享 | 分享链接读取的是同一份 trip 数据快照（最新版） |

## 5. 关键用户流程

### 5.1 首次创建行程

1. 首页点击"开始计划下一段旅程"→ 输入目的地/天数/偏好（一句话即可）。
2. 创建 trip（默认私有），进入工作台三栏页。
3. AI 按框架 → 澄清（选项 chips）→ 确认 → 回写 的循环推进（F2–F3）。

### 5.2 约束变更（实测样例：酒店约束引发环线重排）

1. 用户输入新约束 → AI 比对当前行程，输出"影响面分析"（哪些天受影响、哪里冲突）。
2. AI 给出解决选项 chips（如"↩️ 调整整条环线，让满洲里提前"）。
3. 用户选择 → AI 重排并逐日回写 → 画布/地图同步 → AI 汇报妥协点与遗留待定项。

### 5.3 手动编辑

画布拖拽/卡片菜单/列表视图编辑 → 乐观更新 UI → 后台重算交通段与地图 → 失败回滚并提示。手动改动会在会话流中留下一条轻量系统消息（保证 AI 上下文知晓最新行程）。

### 5.4 分享

点击"分享"→ 生成链接，可见性为"获得链接者可见"；同行人打开为只读三栏视图（可收起 AI 栏）。

## 6. 数据模型（建议）

```ts
Trip      { id, title, startDate, endDate, visibility: 'private'|'link'|'invite',
            owner, shareToken?, days: Day[], stash: StashItem[], notes: Note[],
            checklists: Checklist[], gallery: Media[], createdAt, updatedAt }

Day       { id, index, date, theme, color, items: Item[] }

Item      { id, order, type: 'transport'|'activity'|'stay'|'meal'|'other',
            title, note?, poi?: PoiRef, images: Media[], pending?: boolean }
            // pending = AI 占位待用户确认（如"恩和木刻楞民宿（待定）"）

Leg       { fromItemId, toItemId, mode: 'drive', distanceKm, durationMin, polyline? }

PoiRef    { amapId?, name, location{lat,lng}, category, rating?, photos[], introUrl?,
            introSummary?, recommendSource?: 'ai'|'map-rec' }

StashItem { poiRef, origin: 'recommend'|'favorite', addedAt }   // 待计划池

Message   { id, role: 'user'|'assistant'|'system', content(md), think?, sources?,
            chips?: OptionChip[], createdAt, appliedPatch?: TripPatch }  // AI 回写记录

TripPatch { ops: AddDay|RemoveDay|ReorderItem|AddItem|UpdateStay|...[] }  // AI 结构化回写
```

要点：AI 输出必须落为 `TripPatch`（结构化 diff）而不是整篇文本覆盖，画布/地图是 trip 状态的纯投影；`Message.appliedPatch` 支持"AI 改了什么"的可追溯与撤销。

## 7. 交互细节与状态

- **加载/生成态**：AI 消息生成中显示"思考中…（可展开）"；行程回写期间画布卡片有淡入/移动动画，避免跳变。
- **乐观更新**：拖拽与增删即时生效；交通段与地图路线异步重算，重算中显示骨架/转圈。
- **空态**：无行程时画布显示引导（"问圆周帮你规划第一天的安排"）。
- **错误态**：路线规划失败（如点位太偏）时交通段显示"—"，点击可重试；AI 回写失败保留原行程并在会话中提示重试。
- **收起状态记忆**：三栏收起状态、画布缩放、地图视野按 trip 持久化。
- **响应式**：< 1024px 时三栏变 Tab 切换；地图常驻可呼出。

## 8. 非功能需求

- **性能**：首屏 LCP < 2.5s；AI 回写到画布渲染 < 1s；7 天 × ~20 卡拖拽 60fps；地图 10 万点级推荐 POI 使用聚合/视野过滤。
- **一致性**：行程数据以服务端为权威，三栏为订阅视图；多端打开同一 trip 需近实时同步（轮询或 WS）。
- **权限**：`private`（仅自己）/ `link`（获得链接者可见，只读）/ `invite`（指定账号）。分享页不暴露编辑入口。
- **合规**：地图服务为高德，需按其条款署名；POI 图片与简介外链注明来源；AI 输出带"信息仅供参考，票务/预约以官方为准"提示。
## 9. 边界与异常

- 用户给的时间约束自相矛盾（如行程天数 > 起止日期差）：AI 必须先指出并给选项，不得静默取其一。
- POI 搜索无结果/重名：展示候选列表让用户选，而不是猜。
- 跨天交通段过长（> 6h 驾车）：AI 与交通段组件均应警示并建议拆分/过夜点。
- 待定住宿在行程开始日仍未确认：行前提醒。
- 分享链接可见性从 `link` 收回 `private`：旧链接立即失效（分享 token 状态校验）。

3. 用户提出 10/2 与 10/7 均住海拉尔全季 → AI 指出 10/7 与"住满洲里"冲突，给 chip"↩️ 调整整条环线，让满洲里提前" → 重排后逐日汇报（D5 满洲里：国门 13:30–15:05 压缩是为赶 16:00 大马戏）。

## 附录 B：AI 会话协议（实现建议）

- 内部统一会话接口与具体服务商解耦：应用层只调用 `sessionId 流式发送(消息, 工具定义)`，由 **Provider 适配层**按用户选择的配置翻译为 Chat Completions 或 Responses 格式（见 §4.4）。
- 系统 prompt 要求模型分四类回合输出：`clarify`（问题 + 选项 chips）、`plan`（TripPatch + 概览 + 提醒）、`patch-explain`（改动说明 + 权衡）、`qa`（普通问答，可携带工具调用查 POI/路线/酒店）。
- 模型通过 function calling 产出 `TripPatch`；服务端校验（日期连续性、无重叠住宿、交通段可达）后应用并广播。对不支持 function calling 的用户自接入服务，降级为约定 JSON schema 从文本解析。
- "来源"由检索工具（POI 库/攻略库）的引用列表回填；"思考完成"为 reasoning 摘要（Responses 格式读 reasoning 摘要事件，Chat Completions 读 `reasoning_content`，均无则隐藏该折叠区）。
