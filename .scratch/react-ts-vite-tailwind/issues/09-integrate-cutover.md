# 09: 切换正式入口并移除旧实现

**What to build:** 用户从两个原有入口访问同一完整新版旅行手册，开发者获得可复现、可静态部署且通过全部回归的迁移结果。

**Blocked by:** 05, 06, 07, 08

Status: ready-for-agent

- [ ] 根入口与原旅行页面入口统一进入同一 React 应用，保留原跳转的查询参数及锚点语义；不继续维护两套业务页面。
- [ ] 在所有迁移调用方完成后移除临时入口、兼容桥接及无调用的旧业务脚本和样式；SDK 必需全局、第三方样式及预置大型资源可保留。
- [ ] 应用业务源码采用严格 TypeScript/TSX 与显式依赖，React 管理页面交互，Tailwind 实际承担应用样式，不保留仅包裹旧脚本的空壳。
- [ ] 完整运行既有行为场景的迁移版本及现有纯逻辑测试，不删减或跳过异常用例换取通过；验证搜索、管理、恢复和打印共同使用同一有效住宿安排。
- [ ] 独立类型检查与生产构建成功，静态产物可脱离源码服务器运行；生产预览验证两个入口、资源、配置接入及住宿保存后刷新恢复主流程。
- [ ] 使用旧格式存储和备份验证升级兼容，核对桌面、手机、键盘操作与 A4 打印，不引入视觉重设计或行程变化。
- [ ] 提供依赖安装、Node 要求、开发和启动兼容命令、类型检查、构建、预览、测试及配置文档，说明同源持久化与跨源住宿备份迁移。
- [ ] 交付记录包含实际执行命令、结果和外部依赖验证限制，不沿用历史测试通过数量；保留用户既有变更，不自动部署或修改父规格和已完成的历史票。
