# 03: 集中管理基地与恢复默认住宿

**What to build:** 用户集中管理使用中和备选基地，修改后同步更新行程；可安全删除自定义基地，并将任一晚恢复为原始默认住宿。

**Blocked by:** 01：手动添加住宿基地并用于行程

Status: resolved

- [x] 提供住宿基地管理入口，区分正在使用和未使用的备选，展示关联住宿晚次。
- [x] 编辑自定义基地的名称、位置、类型、地址和备注后，刷新仍保留且所有关联晚次、地图和住宿摘要一致更新。
- [x] 位置变化重算所有受影响路段，保留路线失败提示与异步响应保护；文案修改不导致不相关路线被改变。
- [x] 未使用的自定义基地可直接删除；正在使用的基地必须先替换所有关联晚次，不能产生悬空住宿引用。
- [x] 每晚可恢复原有默认住宿，恢复后地图、计数、相关路线及本地保存一致。
- [x] 默认住宿保留为可选项且不可删除，不允许通过管理操作破坏原计划的恢复能力。
- [x] 浏览器流程验证多晚共用基地编辑、删除保护、替换后删除、恢复默认及刷新恢复，包含路线失败情形。
- [x] 管理、编辑和恢复操作在移动屏幕及键盘操作下可完成。

## Answer

已在 `accommodation.js` 增加原子校验 API：`updateBase`、`deleteBase`、`restoreDay`。编辑自定义基地会同步所有关联晚次；只有位置改变时才让受影响路线进入 `stale`，名称、类型、地址和备注修改不会触发路线重算。默认基地拒绝编辑和删除，使用中的自定义基地删除前必须恢复或替换全部关联晚次。

新增独立 `accommodation-manager.js` 与样式文件，提供使用中/备选/默认基地分组、关联晚次、编辑、替换入口、删除保护及逐晚恢复默认。每日住宿选择器也提供恢复本晚默认住宿操作。

验证：Node 内置测试 3/3 通过；Playwright 浏览器冒烟覆盖共享两晚编辑、坐标修改后的路线未更新状态、使用中删除保护、逐晚恢复、删除备选及默认基地只读，已通过。浏览器测试文件为 `tests/accommodation-manager.browser.cjs`，依赖实现分支提供的共享浏览器 helper。
